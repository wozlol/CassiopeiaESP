# CassiopeiaESP plan

Policy: look up existing standards and code before inventing anything. Every stage ends with a safety step. Do not start a stage until the one before it is marked Done.

## Hardware (verified 2026-11-10)

Board: Freenove ESP32-S3 Display 4.0 inch, SKU line FNK0104, variant FNK0104S (ST7796, 320x480, FT6336U touch). Native USB, no USB-serial chip, so UART0 is free. Sources: https://github.com/Freenove/Freenove_ESP32_S3_Display (sketches, TFT_eSPI setup FNK0104S, schematic 4.0inch_ESP32-S3_Display_Schematic.pdf)

Do not mix up with the classic ESP32 line (FNK0103, FNK0114), its pins differ.

| Function | GPIO |
|---|---|
| Display SPI | MOSI 11, SCLK 12, CS 10, DC 46, BL 45, RST none |
| Touch I2C (FT6336U) | SDA 16, SCL 15, RST 18, INT 17 |
| Audio codec ES8311 | I2C shared with touch (15/16), MCK 4, BCK 5, WS 7, DIN 6, DOUT 8, amp enable 1 |
| SD card (SD_MMC 4 bit) | CLK 38, CMD 40, D0 39, D1 41, D2 48, D3 47 |
| RGB LED | 42 |
| Boot button | 0 |
| Connectors | UART: TXD0 (43) RXD0 (44) with 100R, 5V, GND. I2C: IIC_SCL 15, IIC_SDA 16 shared bus. Extended IO: IO2, IO3, IO14, IO21 |

Free for us: IO2, IO3, IO14, IO21, 43, 44. The shared I2C bus is live with touch and codec.

nRF52832 (SparkFun breakout WRL-13990, retired). Source: https://learn.sparkfun.com/tutorials/nrf52832-breakout-board-hookup-guide
- C and D are the SWDCLK and SWDIO test points, not a UART.
- Serial bootloader UART is P0.26 RX and P0.27 TX, entered by holding P0.06 low at reset. Reflashing over SWD erases it. Restore hex is in the SparkFun GitHub repo, Firmware/bootloader-custom.
- 3.3 V can feed the 3.3V pin directly, range 1.7 to 3.6 V.
- Cut the PWR-LED jumper and consider the RTC-EN jumper for sleep current. The power LED draws 1 to 2 mA.

Keybed: Casio A-11 4MB, marking z305-KY C140360-1. No public matrix map found (searched 2026-11-10). Windows CE has no standard scan codes. Open leads: the 87 page A-11 service manual on ManualsLib.

## Product

One handheld, up to three firmware modes loaded from the SD card, one running at a time so none shares RAM with another.

- Mode 1 is the daily driver. Terminal sessions that persist, cached text docs, clipboard manager, file browser, media player, text and md editor, and search of the survival database if it fits. A rudimentary web browser later, rendered by a worker on the host PC.
- Mode 2 is the AMY synth with the FoxWizard arp, loop and stutter feature set. It may not fit beside Mode 1 and must never share RAM with it.
- Mode 3 is the database and lookup utility, only if search does not fit in Mode 1.
- Build order is Mode 1 first.

Mode 1 MVP, in order of importance:
1. Switch between terminal sessions. Sessions live in tmux on the PC, so they persist across device power cycles, sleep and wake, and can be closed and rejoined. The device remembers its session list.
2. Full sleep and wake with the on and off keys.
3. Brightness key cycles backlight levels.
4. GUI key opens the device menu and clipboard manager. Ctrl plus GUI goes straight to the clipboard manager.
5. Ctrl plus minus and Ctrl plus equals change font size, saved across power cycles.
6. Default theme is black background with neon green text (#39FF14 on #000000). Colors come from a theme table so more themes can be added without touching drawing code.

Then, in Mode 1:
- Cached text docs (Google Docs, later Sheets). No true multitasking, only quick switching between sessions and docs.
- Network control panel, one easy URL on the LAN or a phone hotspot. First version manages SD files and moves text in and out of the clipboard manager. More comes later.
- Web browser, with room left for it.

Design notes:
- Session persistence is tmux on the PC. The ESP only attaches and detaches. The ESP persists only the session list and settings.
- Google credentials stay on the PC worker, never on the handheld. The worker exports docs to text or md in the SD cache, and pushes device edits back later. Google Docs has no offline merge, so a sync is a whole doc replace, and if the doc changed online in the meantime both versions are kept and the user chooses. Sheets come after Docs.
- Modes are separate app images in OTA slots plus a small loader. Copy a mode image from the SD card into a slot once, then switch by setting the boot slot and rebooting. This needs flash size and the partition table decided early, see stage 5.
- The browser worker runs sites on the PC in a sandbox (separate low privilege user or container) and sends back a compressed, interpreted view. The device never runs site code.

## Open decisions

1. Decided 2026-11-10: UART header pins 43 and 44 are bit banged SWD to C and D (flash and updates), the shared I2C connector is the runtime link with the nRF as an I2C slave, IO3 is the nRF to ESP interrupt and wake line.
2. Decided 2026-11-10: keep PCM5102A on IO2 (BCK), IO14 (LRCK), IO21 (DIN) for stereo line out for the AMY synth. The onboard ES8311 and speaker stay for terminal sounds. 2026-11-23: the user is using only the built in speaker and microphone for the foreseeable future, the PCM5102A is parked.
3. Decided 2026-11-11: the SSH key on the handheld is stored encrypted. It unlocks with a PIN typed on screen, or by holding a chord before pressing On. The chord is On plus exactly two ghost free keys (Shift, Ctrl, Alt, GUI, Caps Lock) with nothing else held, it cannot be typed as a PIN. Both are set in settings while logged in. Only a few chords exist so wrong tries lock out. On a trusted network the panel and tabs open without a key. On an untrusted network (phone hotspot, internet) a PIN is asked each connect. Trusted means the device recognizes the worker by its fingerprint, never by Wi-Fi name alone.
3b. Decided 2026-11-11: every device has its own identity key. The PC worker keeps an allowlist and refuses anything not on it, so other devices built later are paired one by one with a PIN and can be revoked one by one.
4. Open, decide after measuring on the real data: search is tiered. PC worker searches first when reachable (full Wikipedia, instant). Local fallback is a title index for everything, a word index for the small survival and health set, and a plain scan of the compressed text for the rest (a minute is acceptable). Compare against the existing Offline-Wikipedia-ESP32 project (custom fixed width title index on the SD card) before building.
5. Decided 2026-11-11: one worker on the home machine does tmux control, scrollback caching, Google sync, Apple Notes sync, clipboard sync and later browser rendering. Notes use icloud-md (coddingtonbear/icloud-md, TypeScript CLI, runs on Linux, Windows or macOS, md files in a folder, syncs both ways). It is unofficial and uses a private iCloud service, so see the ledger. Reach the worker from outside only through the WireGuard tunnel, never a port per service. Open: which machine runs it.
6. Open: stage 5 evaluates the existing bmorcelli Launcher (writes SD images into OTA slots with Update.h, CYD boards supported) before we write our own loader. Both modes live in flash if the flash size allows, otherwise copy from the SD card at each switch.
7. Decided 2026-11-11: Mode 1 moves to ESP-IDF (Esperdeck needs 6.0.1) so its parts drop in. nrf_tool stays a small Arduino utility until it is ported.

## Reuse first

Policy: lean on existing code for every part. Primary base is sigman78/esperdeck (MIT, https://github.com/sigman78/esperdeck, an SSH terminal for a Waveshare 7 inch ESP32-S3 board). Reusable as is or nearly: components tsm (terminal state machine, VT100 to xterm, 256 color, alternate screen, scrollback), vterm, font (Terminus bitmap, compressed C tables generated from the BDF), libssh2_esp with mbedtls PSA and ed25519 via monocypher, keystore (Argon2id and XChaCha20-Poly1305), host key pinning, LittleFS storage, Wi-Fi onboarding portal with QR code, board and input components as patterns. Not reusable: its display driver (800x480 parallel RGB, no framebuffer, draws inside the DMA interrupt) and its Bluetooth keyboard input. Our panel is SPI ST7796, our keyboard comes from the nRF, so display and input are ours. Candidates to look up for the rest: md4c (markdown parser) for the md reader, ESP-IDF esp_lcd for the ST7796 panel, AMY (shorepine) for the synth, icloud-md for Notes.

Modularity: board, display, input, storage and network are separate components behind small interfaces, with one board profile file holding pins and screen size. A new screen, keyboard or S3 board should need a new profile and at most a new driver, not changes to the apps.

Facts confirmed 2026-11-11: board has a microphone (ES8311 MIC1 plus an onboard mic, schematic), ESP32-S3R8 gives 8 MB PSRAM, flash is 16 MB (esptool flash-id 2026-11-12, chip ESP32-S3 QFN56 rev v0.2, 8 MB PSRAM). Two or three mode images fit in flash at once, so switching is a reboot and the SD card is only the source for installing and updating modes. Default terminal font is 6 pixels wide (80 columns on 480 px) and the user can squish or grow it with Ctrl minus and equals. Check that Terminus has a 6x12 face when adding it to the font generator, and if not use another 6 pixel wide bitmap font.

## Media viewer and reference reader, draft 2026-11-23

Two firmware images on the loader, not one and not part of Mode 1. They share components, not RAM.

Decisions from the user: sound comes from the board's own speaker (ES8311), the microphone stays unused for now, the PCM5102 module is parked. Wiki and survival data come as Kiwix ZIM files. Reader search is title first, full text second. Reader formats for the first draft are plain text, Markdown, HTML and PDF. Text keeps the same text sizes, themes, scroll keys and brightness key as the terminal.

Same or separate: separate. Video and music want big decode and audio buffers and a steady CPU, the reader wants big index and article buffers. Mixing them in one image would make each fight the other for RAM, and the product rule is one mode at a time with its own RAM. What they share is code:
- prefs: themes and settings, so size and theme chosen in Mode 1 apply in both (new component, split out of ui).
- sdcard: SD_MMC 4 bit mount, one place (new component, the loader's code moved).
- display: the text grid and fonts as now, plus a raw bitmap mode for pictures (new).
- a11_keys and touch as now.
- A small picture decoder (JPEG, esp_jpeg) is in both so the reader can show simple pictures in articles.

### Media viewer (modes/media)
- Card layout: /media, any folders. A file browser with the Mode 1 look, Enter opens, Esc goes up.
- Formats on the device: pictures JPEG (PNG and BMP later), music WAV and MP3. Video was dropped by the user on 2026-11-23, no video player will be built.
- Converter on the computer: tools/a11convert.py using ffmpeg (installed). Pictures to 480 wide JPEG, video to 480x320 MJPEG AVI at 15 fps with mono PCM, music to MP3 or WAV.
- Pieces taken as they are: esp_jpeg (Espressif, TJpgDec) for pictures and frames, minimp3 (single file, public domain) for MP3, esp_codec_dev (Espressif) for the ES8311 codec, ESP-IDF I2S. Own: the AVI chunk reader and the player loop.
- Keys: Space or Enter pause, Left and Right seek 10 s, Up and Down volume (capped in code), Esc back, backlight key as always. Touch: tap pauses, drag seeks.
- Stages: 1 pictures and browser, 2 WAV and MP3 through the speaker, 3 playlists and resume position. Done check per stage: plays a sample from the user's computer, frame rate read from the log.
- Risks: software JPEG speed at 480x320 (target 15 fps, measure first), SD read speed, the audio chip needs its power amp pin (GPIO1) and shares the I2C bus with touch.

### Reference reader (modes/reader)
- Text viewer: txt, md, html, pdf. HTML is cleaned to text on the device. PDF text is pulled out on the computer (tools/a11convert.py), scanned PDFs will not work. Markdown shows headings bold, lists and code with theme colors. Wraps to the text grid, scrolls with the terminal keys, search inside a page with Ctrl+F.
- Packs: tools/a11pack.py turns a ZIM file into a folder on the card (title index sorted for binary search, articles in compressed blocks, small JPEG pictures, link table). The device cannot read ZIM directly, its blocks are larger than free RAM, so every existing ESP32 Wikipedia reader converts first.

## Future machines, noted 2026-11-27

The same firmware idea, a keyboard handheld that runs a terminal, a reader and a media viewer, is planned for a second machine later, such as an HP or Sharp pocket computer. The first Casio programs stay in the project as reference for that port: modes/reader, modes/media, modes/shell0, modes/keytest, modes/screentest, modes/hello and modes/tailnet. They are no longer installed on the card. The Library program (modes/library) replaced the reader and media. The shared pieces to carry over are the components: app_reader, app_media, app_files, app_common, display, a11_keys, ui, webadmin, keystore and sessions.
